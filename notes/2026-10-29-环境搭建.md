这四个工具分两组记：ESLint + Prettier 管代码本身（一个管"对不对"，一个管"好不好看"），Error Lens + GitLens 管信息显示（一个把错误放大，一个把历史摊开）。逐个讲：

ESLint：抓错的（红色/黄色波浪线的来源之一）

它是一个"静态检查器"：不运行代码，只按一套规则扫描你的 JS/TS，比如"变量声明了没用""用了 == 而不是 ===""React 的 hooks 调用位置违规""引用了不存在的函数"。它在代码跑起来之前就拦住低级错误，是"工程素养"的第一道闸。使用要点：鼠标悬停在波浪线上看规则名和解释；旁边的小灯泡（Quick Fix）能一键修掉一部分；底部"问题"面板能看整个项目的清单。

但有个对你重要的实话：现在它没活干。ESLint 需要项目里装 eslint 包和规则配置才生效，你现在还没有项目。插件先装着，等你 S1 末尾建第一个 Vite 项目时，我会带你把它配起来——那之后"项目零 ESLint 错误"就是我们每阶段的通过标准之一。

Prettier：排版的（不判断对错，只统一长相）

它不管逻辑，只管格式：缩进几个空格、单引号还是双引号、行尾分号、超过 80 字符自动换行。价值是风格统一、代码 diff 干净，读代码时眼睛不被格式噪音干扰。你已经设好"保存时自动格式化"，所以它现在是静默工作的：每次 Ctrl+S 自动整理。手动触发是 Shift+Alt+F。记住它和 ESLint 的分工：ESLint 管对错，Prettier 管长相——代码被排整齐了，错的地方还是错，别把"变整齐"当成"变对了"。

Error Lens：把错误甩到你脸上的

VS Code 原生的错误只是画条波浪线，信息要悬停才出现，很容易被忽略。Error Lens 直接把错误文字渲染在出问题那一行的行尾。它本身不产生任何检查，只是把已有诊断（VS Code 内置的 JS/TS 检查 + ESLint）放大显示。对零基础的你很合适：错误无处可藏。装上即用，零配置。以后写 TypeScript 时，它就是"实时显示类型错误"的加速器。

GitLens：让你看见代码的历史

Git 的本质是快照：每次 commit 保存一份当时全项目的状态。GitLens 把你和这些快照之间隔着的命令行拆掉了——你能在编辑器里直接看到：这一行是谁、哪次提交、什么说明改的（行尾 blame 注释）；这个文件的完整历史；某个函数被哪些提交改过。它的正确用法是当"可视化阅读器"：先用命令行学会 git log、git diff、git blame 这三个基本功，GitLens 是它们的一键版，不是替代品。

在你每天的流程里，它们是这样排队的：写代码 → ESLint 和 Error Lens 实时标出问题 → 你自己读懂、自己修 → 按 Ctrl+S 时 Prettier 自动排版 → 提交时用 GitLens 回头看"这次改了什么、和历史有什么关系"。

第二步：本地初始化并推送

先打开终端，进入项目文件夹（你之前的 PowerShell 就可以），依次执行：

cd D:\实习冲刺前端
git config --global user.name "你的名字拼音或昵称"
git config --global user.email "你的GitHub注册邮箱"
git init
git add .
git commit -m "init: 初始化学习仓库，加入6个月冲刺计划"
git branch -M main
git remote add origin https://github.com/你的用户名/frontend-sprint.git
git push -u origin main
每行在干什么，逐条解释：

git config 两行：告诉 Git "你是谁"，每次提交都会带上这两个信息，只需要设置一次
git init：把当前文件夹变成一个 Git 仓库（本质是多了一个隐藏的 .git 文件夹记录所有历史）
git add .：把文件夹里所有文件放入"待提交区"（暂存区）
git commit：拍下第一个快照，引号里是这次快照的说明文字
git branch -M main：把主分支命名为 main（GitHub 的默认叫法）
git remote add origin ...：给本地仓库登记远程地址，origin 就是"GitHub 上那个仓库"的代号
git push -u origin main：把本地历史推送到 GitHub。第一次会弹出浏览器让你登录 GitHub 并授权，点 Authorize 就行
可能遇到的两个问题：

git push 卡住或报网络错误：梯子没开或断了，开好再试
报 rejected / non-fast-forward：说明建仓库时勾了 README，远程已有内容。最简单：删掉 GitHub 上那个仓库重新建（这次什么都不勾），再来
做完验证：刷新你的 GitHub 仓库页面，能看到 前端实习冲刺-6个月学习计划.md；终端里跑 git log --oneline，应该有一行提交记录
f6caca1 是这次提交的快照编号（hash），全世界唯一，以后任何时候都能凭它找回这次提交的内容
HEAD -> main 表示你本地当前站在 main 分支的这个快照上
origin/main 和它挨在一起，说明 GitHub 上的远程仓库也指向同一个快照，推送成功
以后看到括号里两个分支对齐，就是"本地和远端一致"。这就是昨天说的"快照叠加成历史"，你已经亲手拍下第一张了。
